# OAKOC Process

本项目把 OAKOC 地形分析整理为一套可以运行和继续扩展的 Python 代码框架。
程序从任务请求开始，依次完成变量需求、数据准备、三项基础分析、综合分析和成果发布，
并为十三个步骤分别记录运行状态。

## 1. 当前能做什么

当前版本可以：

- 读取一份完整的 JSON 任务请求；
- 判断本次任务需要哪些变量以及哪些必要输入仍然缺失；
- 按正确的前后关系执行十三个步骤；
- 分别调用障碍、观察与射界、隐蔽与掩蔽、候选关键地形、接近路线和关键地形复核；
- 在终端显示完整 JSON，或者将结果保存为 JSON 文件；
- 拒绝在正式模式中发布示例结果。

当前版本是代码框架，不会下载真实公开数据，也没有实现重投影、裁剪、质量计算、
OAKOC 公式和地图渲染。六项分析目前返回明确标记为 `placeholder: true` 的示例结果，
因此完整运行状态为 `degraded`，不能作为实际地形分析结论。

## 2. 十三步流程

| 步骤 | 内容 | 作用 |
|---|---|---|
| 1 | 运行上下文与变量需求生成 | 明确区域、时间、主体、任务目的和所需变量 |
| 2 | 数据获取 | 登记公开数据、任务数据和现场观测 |
| 3 | 数据统一 | 统一名称、位置、时间和单位 |
| 4 | 质量检查与公共地形计算 | 检查覆盖和质量，准备坡度等公共数据 |
| 5 | 建立分析基线 | 形成六项分析共同使用的数据基础 |
| 6 | 障碍分析 | 预留障碍区、通行成本和限制计算入口 |
| 7 | 观察与射界分析 | 预留可视范围、盲区和射界计算入口 |
| 8 | 隐蔽与掩蔽分析 | 预留隐蔽区、掩蔽区和暴露范围计算入口 |
| 9 | 基础结果汇总 | 汇总步骤 6 至 8 的结果 |
| 10 | 候选关键地形识别 | 先形成候选，不提前确定最终关键地形 |
| 11 | 接近路线分析 | 使用基础结果和关键地形候选分析路线 |
| 12 | 关键地形复核 | 结合任务效果和路线控制关系进行复核 |
| 13 | 综合校验与发布 | 输出缺口、地图待办、结构化结果和说明 |

步骤 6 至 8 在分析基线形成后可以分别执行。步骤 10 至 12 必须使用前面已经形成的
基础分析结果，这也是代码中分析依赖关系的主要依据。

## 3. 文件说明

| 文件 | 功能 |
|---|---|
| `OAKOCProcess.py` | 命令行入口；读取请求、运行流程并输出完整 JSON |
| `oakoc/__init__.py` | 集中公开外部程序最常使用的类和函数 |
| `oakoc/models.py` | 定义任务输入、变量、来源、质量、步骤和结果的数据格式 |
| `oakoc/catalog.py` | 登记 66 个 P0/P1 变量和 10 个公开数据来源 |
| `oakoc/analyzers.py` | 定义六项分析函数的统一调用方式和当前示例实现 |
| `oakoc/pipeline.py` | 生成变量需求，执行十三步流程并汇总发布结果 |
| `examples/full_process_request.json` | 默认实例输入，包含任务、区域、模拟数据和全部分析设置 |
| `examples/full_process_result.json` | 使用默认实例完成一次运行后保存的完整结果 |
| `tests/test_pipeline.py` | 检查流程顺序、依赖失败、变量需求和正式模式限制 |
| `tests/test_full_process_example.py` | 从外部 JSON 读取到结果写出的完整命令行测试 |
| `docs/variable-design.md` | 按十三步说明变量、公开来源、缺失处理和第一版范围 |
| `pyproject.toml` | 记录 Python 版本、项目名称和依赖 |
| `uv.lock` | 固定依赖的实际版本，使不同机器使用相同环境 |
| `.gitignore` | 排除缓存、日志和本地环境文件 |

实例中的 `fixture://` 表示模拟数据地址。它只用来展示数据应如何登记，程序不会访问网络，
也不会把这些地址写成已经取得的真实数据。

## 4. 运行方法

项目要求 Python 3.11 或更高版本，并使用 `uv` 管理运行环境。以下命令都在项目根目录
`OAKOC` 中执行。

### 4.1 运行默认实例

```bash
uv run python OAKOCProcess.py
```

程序默认读取 `examples/full_process_request.json`，并在终端显示完整 JSON。这个命令不会
保存新的结果文件。

### 4.2 运行实例并保存完整结果

```bash
uv run python OAKOCProcess.py \
  --input examples/full_process_request.json \
  --output examples/full_process_result.json
```

完整 JSON 会保存到下面的文件，终端不再重复显示结果：

```text
examples/full_process_result.json
```

### 4.3 使用自己的请求

```bash
uv run python OAKOCProcess.py --input request.json --output result.json
```

`--input` 可以省略，省略后使用默认实例。`--output` 也可以省略，省略后在终端显示完整 JSON，
不会保存完整 JSON。

### 4.4 运行测试

```bash
uv run python -m unittest discover -s tests -v
```

## 5. 完整 JSON 结果

`full_process_result.json` 主要包含：

| 字段 | 内容 |
|---|---|
| `run_id` | 本次运行的唯一编号 |
| `status` | 完整流程的最终状态 |
| `context` | 原始请求、变量需求、已登记变量和数据准备提示 |
| `stages` | 十三个步骤各自的状态、时间和说明 |
| `analyses` | 六项分析结果、适用范围、可信程度和限制 |
| `validation_issues` | 发布前发现的完整性问题 |
| `output` | 地图待办、结构化章节、数据缺口和综合说明 |

每次运行都会重新生成 `run_id` 和步骤时间，因此覆盖结果文件后这些字段发生变化属于
正常现象。
